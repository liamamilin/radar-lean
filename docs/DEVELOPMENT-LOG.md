# Radar 开发记录（V0.1 – V0.2 逐轮验证与已知限制）

> 这是开发过程中的逐轮记录，保留当时的真实验证结果和限制。产品说明见仓库根目录 README.md。


macOS 原生信息雷达：自然语言建立关注 → 发现并试读信息源 → 定期直接采集 → 基线/去重 → 带原始链接的事件。

- 技术栈：SwiftUI · GRDB(SQLite) · FeedKit · SwiftSoup；无需任何 API Key（GitHub Token 可选，存钥匙串）。
- 构建：`scripts/build_app.sh` → `dist/Radar.app`（ad-hoc 签名，macOS 15+）。GRDB 以浅克隆放在 `ThirdParty/GRDB.swift`（官方仓库完整克隆在本机网络下过慢）。
- 测试：`swift test`（fixture + URLProtocol，A–F 六组行为）；真实联网：`RADAR_LIVE=1 swift test --filter LiveTests`。
- 数据库：`~/Library/Application Support/Radar/radar.sqlite`（环境变量 `RADAR_DB` 可覆盖）。

代码：`Sources/RadarCore`（Models/Fetch/Engine/Plan/Discovery）、`Sources/Radar`（SwiftUI App、菜单栏、设置）。

## 联网搜索信息源（新增）

设置里填 Exa API Key 后，主题类关注会先联网搜索，再对结果站点探测 RSS/Atom（按站点去重，跳过 GitHub 与社交站），探测通过的才作为候选列出。未填 key 时退回内置目录和 GitHub 搜索。已用 URLProtocol 桩测试；未用真实 key 实测（没有 key）。

## 第二轮迭代：发现与判断（真实运行结果）

- **GitHub 发现**：两个窗口合并（90 天内 ≥30★ 前 100 + 14 天内 ≥5★ 前 50），排除 fork/归档；“新项目”按创建时间判定，不是首次看到时间。门槛默认 50★（创建 14 天内降为 1/5，至少 10★），要求有描述且不是“只有星标没有 fork”，可在计划里改。
- **无 RSS 站点**：识别文章/项目列表页（最大同结构链接组，≥5 条；“Read more”类链接取卡片标题），每条独立去重。真实站点 thecontext.dev、research.meta.ai、index.zshipu.com 读取成功。
- **事件分级**：`newProject` / `majorUpdate`（正式版 major/minor 升级、标题含 release/发布等）/ `pageChange` / `update`。主题类关注只对前两类弹系统通知，其余只进列表。
- **跨来源合并**：同一关注下相同链接/GitHub 仓库/标题的内容只留一个事件，各来源出处合并显示。
- **自然语言**：验收句不再把“有真正值得关注的新项目时提醒我”当关键词；语义条件（如“创新”“中文”）列为“未生效”；Stars 门槛可一句话设置；修改关键词后自动重新发现并挂接新来源（不补报历史），对不再匹配的来源给出提示，来源可手动移除。
- **真实场景**（`RADAR_LIVE=1 EXA_API_KEY=… GITHUB_TOKEN=… swift test --filter ScenarioTests`）：来源发现 9 秒，7 个来源、567 条基线、0 事件；模拟新增后 31 条事件均带来源链接；重复检查 0 新事件；“也关注 MCP，排除 RAG”后新增 3 个来源，只记基线。
- **真实 App 驱动**（`RADAR_DRIVE_*`，见 ContentView.drive）：在运行中的 App 里走完新建→检查→暂停/继续→增量→自然语言修改，每步截图；来源 4→7，13 条事件，无重复 mergeKey。

**未解决**：没有用鼠标点过界面（osascript 无辅助功能权限，用 App 内置驱动代替，未验证真实点击与系统通知弹出）；LLM 辅助判断没有做（只有确定性规则，Foundation Models 本机不可用）；质量规则较粗，仍会放进少量低质量仓库；暂停期间出现的内容恢复后不补报；主题目录仍只有 AI 一类；JS 渲染页面不支持。

## 第三轮迭代：正确性与信息质量

- **事件合并漏报已修**：同一网页的新内容版本（同标题）逐次产生事件；仅在“同链接 / 同一 GitHub 项目（7 天内）/ 另一来源同标题（3 天内）”时才合并并保留各来源证据。同一来源复用标题、不同链接不合并。
- **已有项目重新获得关注**：GitHub 来源每次采集更新已有项目的 Stars/Forks；某个 Watch 的门槛被首次跨过时产生一次“项目升温”事件（12★→300★ 已测），已通知不重复，各 Watch 门槛独立，首次建立只记基线。搜索按星标分三个区间（14 天≥5、90 天 30–400、90 天 >400）取各自前 100，避免被高星项目挤掉；请求按 GitHub 限额自动间隔。
- **通知分类**：主题类 Watch 只对 `newProject` / `majorUpdate` 弹系统通知（`Engine.shouldNotify`），其余留在列表；通知开关仍有效。
- **质量规则**（用真实 ai-agents / local-llm / mcp 样本检查后调整）：相关性看名称+描述，仅靠 topic 标签命中时必须读起来像 AI 项目（CAD、UI 库、邮件工具被挡掉）；≥200★ 而 fork 不足 1% 视为虚高；ASCII 关键词按词首匹配（agent 不再命中 management）；同一仓库的文章与仓库事件归并。
- **测试**：34 个（3 个联网类默认跳过）。新增回归覆盖：同标题网页连续变化、跨来源重复、跨门槛一次提醒、未跨门槛、通知分类、自然语言排除生效、质量规则；`LocalServerTests` 用真实本地 HTTP 服务器，文件内容真的变化（页面、RSS、列表页、GitHub 指标），不改数据库；`RecheckTests` 对真实 GitHub 间隔 4 分钟重采：290 个项目中 15 个 Stars 真实变化，指标被更新，立即重查无新事件。LiveTests 里 `|| true` 的无效断言已删除。
- **真实 App 驱动**（无 key、真实 GitHub、真实等待 150 秒）：创建→暂停/继续→重采（509 个项目，18 个 Stars 变化，新增 1 个新项目事件）→“也关注 MCP，排除 RAG”新增 MCP 来源并保留旧来源。

**仍未解决**：没有用鼠标键盘实际点过界面（osascript 无辅助功能权限，仅 App 内置驱动）；系统通知弹出、菜单栏重新打开窗口、关闭窗口后后台继续监测未实测；真实 GitHub 上还没有等到某项目恰好跨门槛的实例（本地服务器测试覆盖）；Exa 联网发现本轮 App 内未重跑（上一轮已用真实 key 验证）；超过 90 天的旧项目突然走红不在搜索范围内；质量规则是确定性启发式，仍会有误判；LLM 判断未做。

## 真实界面操作验证（辅助功能授权后）

用 System Events 对 `dist/Radar.app`（临时数据库、真实 GitHub、无 key）做了真实的按钮按压与键盘粘贴：新建关注（输入验收句、分析、开始关注）→ 暂停/继续 → 立即检查 → 在自然语言框粘贴“也关注 MCP，排除 RAG”并点应用（关键词与排除更新，新增 MCP 来源，旧来源保留）→ 新建 RSS 关注，本地 feed 真实新增文章后立即检查，事件带原文链接 → 删除关注（无人使用的来源一并清掉）→ 关闭主窗口后 App 仍在运行，菜单栏“立即检查全部”仍会重采，“打开 Radar”重新打开窗口 → 菜单栏退出。

**未能验证**：系统通知横幅（事件已产生，但没有抓到横幅，授权状态未知）；真鼠标点击坐标/拖动（用的是辅助功能按压，不是物理鼠标）；Exa 联网发现的界面流程（本轮无 key）。

## V0.1 收尾（本轮）

- **事件合并**：事件按「发生了什么」(facet：`discover` / `release:<版本>` / `article:…` / `page`) 区分。同一 GitHub 项目的“首次发现 → v1.0 发布 → 重大更新”是不同事件；多个来源报道同一件事合并，保留全部证据链接；网页内容版本各自独立；已通知的事件不重复通知。无实体/语义聚类。
- **检查不重叠**：同一来源同时只会被抓取一次（进行中则跳过），详情页显示“检查中…”；定时、暂停/继续、唤醒补查不变。
- **来源试读**：GitHub 搜索先用轻量查询，空时回退 14 天窗口，只有 5–29★ 的近期项目也能被识别为有效来源。
- **通知**：只有新项目 / 重大更新弹系统通知；普通更新留在 App 内。菜单栏在系统通知被拒绝时显示“系统通知已关闭 — 打开系统设置”。
- **测试**：38 个（4 个联网类默认跳过）。

**真实限制（请知悉）**：
- **系统通知**：在 系统设置 → 通知 里允许 Radar 后，授权通过，本地 feed 的新文章通知已送达通知中心（已截图确认）。首次未允许时 `requestAuthorization` 返回 “Notifications are not allowed”，菜单栏会提示去系统设置。横幅的瞬时显示与点击通知打开链接尚未验证。
- 不做 JS 渲染页面、超过 90 天的老项目走红、LLM 判断；质量规则是启发式，会有误判。

## V0.2 Intelligence：AI 总结与问 Radar（本机 Ollama）

规则负责高频采集，AI 只在你主动点击时运行：采集、去重、通知都不调用模型，Ollama 关掉后 V0.1 的全部功能照常可用。只用本机 Ollama（`127.0.0.1:11434`），不联网、不需要 Key；云端模型（`*-cloud`）和纯 embedding 模型不会出现在列表里。

- **设置**：设置 → “本机 Ollama” 显示连接状态、已安装模型并可切换；总结/问答界面里的模型名也可直接切换。没有模型时提示用 `ollama pull <模型名>` 安装（Radar 不会自动下载）。
- **AI 总结**：关注事项详情页的 “AI 总结” 和侧栏 “AI 简报”（全部关注事项）。可选 24 小时 / 7 天 / 30 天 / 全部。**“事件”（真实新变化）与“已发现内容”（含首次采集的基线）分开提供给模型**，没有事件时会明确写“没有检测到新事件”，不会把基线说成新增。结论带 `[S编号]`，点击跳到原文；来源链接来自数据库，不是模型生成的。生成后缓存，重新打开不重复生成；数据变化时提示“可重新生成”。
- **问 Radar**：侧栏 “问 Radar”（或某个关注详情页里的 “就这个关注事项问 Radar…”，此时只检索该关注）。从本地 SQLite 做关键词检索（范围、时间、标题/正文匹配，按相关性/星标/新近排序，限制条数与长度）再交给模型，流式输出，可停止、可继续追问（追问沿用之前的资料和编号）。资料不足时会直接说明。
- **不做**：不引入向量库/Embedding/云端 LLM/多 Provider；不联网搜索；不按需抓原文。

**真实限制**：
- 回答质量取决于你选的本地模型和已采集的内容；新闻汇总类来源（日报/周报）里一篇文章可能包含很多条目，模型有时会把它们当作“项目”。检索是关键词匹配，不懂同义词，问题措辞太泛时会退回按新近/星标排序。
- 8B 左右的本地模型，总结约 30–60 秒（含模型首次加载），问答约 10–30 秒。
- 不会根据简短描述判断兼容性/性能；但这是提示词约束，小模型仍可能越界，请以原文为准。
- 默认选第一个非 thinking 的本地模型，可能不是你想要的（如自定义模型），请在设置或界面里切换。

## V0.3：外部大模型、每日分层简报、问 Radar 对话与读链接

这一轮取代了 V0.2 里“不做云端 LLM / 多 Provider”的决定：Ollama 仍可用，另可接任意 OpenAI 兼容服务（预设 OpenCode Go）。采集、去重、通知仍然不调用模型。

**先修的几个小问题**
- **推送图标是占位图**：`AppIcon.icns` 一直在包里，是 macOS 按 Bundle ID 缓存了加图标之前的占位图；用 `lsregister -f` 重新注册并清图标缓存后刷新。不是代码问题。
- **回答无法选中复制**：SwiftUI `Text` 加 `.textSelection` 会吞掉 `[S1]` 链接的点击，两者不能兼得。`MarkdownText` 改用 `NSTextView` 渲染（标题、列表、粗体、行内代码手工排版），既能拖选 / ⌘C，链接也照常点击并走 `LinkOpener`；另有“复制”按钮，复制原始回答文本。
- **问“最近 24 小时更新了什么”只回一点点**：检索对这类问题只取约 3 条事件 + 10 条内容（共 <18 条），提示词还限定“不超过 8 条”，而且“时更”“新了”这类无意义二字词在做关键词匹配。新增 `isOverview` 识别概览型问题（只含时间和“更新/动态/有啥”这类泛词），此时不做关键词匹配，按新鲜度取材，各关注事项轮流入选，事件最多 8 条、内容最多 22 条、总数最多 30 条，回答上限放宽到 15 条。点名了对象的问题（如“Claude Code 最近更新了什么”）仍走原检索。

**1. 外部大模型**
- 新增 `ChatClient` 协议，`OllamaClient` 与新的 `OpenAICompatClient` 都实现它；后者请求 `{base}/models` 与 `{base}/chat/completions`（SSE 流式，跳过 reasoning 字段），错误分为没填 Key / 连不上 / Key 无效（401、403）/ 服务端报错并显示其消息。
- 设置 → “AI 模型”：来源（本机 Ollama / OpenAI 兼容服务）、服务预设（OpenCode Go：`https://opencode.ai/zen/go/v1`，或自定义地址）、API Key（系统钥匙串，沿用“只在用户保存过才在启动读取”的做法避免每次重新打包弹钥匙串）、“保存并测试”、模型列表（从 `/models` 拉取）。
- 切换来源时各自记住所选模型；改来源时飞行中的刷新结果会被丢弃，避免串台。
- 用外部服务时，设置页明确提示：生成总结或提问会把检索到的资料片段（标题、摘要、链接）发给该服务。

**2. 每日分层简报**（侧栏 “AI 简报”，实测后重做过一版）
- **每天一份**：简报按日期保存，顶部 ◀ 日期 ▶ 切换，也可从菜单选历史某天；过去的日子只读。不再有“重新生成整份”。
- **雷达用标签页区分**：第一个标签“总览”，其后每个关注事项（雷达，如“开源大模型发布雷达”）一个标签，带当天更新条数；标签栏可横向滚动。
- **每个雷达可单独生成**：在对应标签页点“生成这个雷达的简报 / 重新整理”，只对它调用一次模型，不会动其他雷达，也不重写总览。没有新内容的雷达不调用模型，直接记为“没有新内容”。
- **总览**：由各雷达小节汇总（一次模型调用，不带引用，也不再重复写“总览”标题）。某个雷达在总览之后又被重新整理时，总览会提示“有雷达的内容比这份总览新”，可点“更新总览”单独重写。总览页下方列出各雷达的状态（未生成 / 没有新内容 / N 条事件 · M 条内容），每行可直接生成；“生成全部”只补齐未生成的，“全部重新生成”需确认。
- **边生成边保存**：每个雷达写完就存，标签页逐个出现；中途停止或失败，已写好的保留。
- **自动生成**：开关 + 时间（默认 07:00）。每分钟、启动时、唤醒时检查“已过设定时间且今天还没有总览”，满足就补齐今天缺的小节再写总览（已手动生成的不重做）；模型不可用时每 15 分钟重试。自动完成且有更新时弹通知，点击打开简报页。
- **存储**：表 `briefing`（迁移 v8），每天只保留一份（同一天保存即原地替换）；旧格式的简报会按其生成时间升级，不会被当成“缺失”而重跑。关注事项详情页里的“AI 总结”面板不变。
- **排版 bug（已修）**：简报里的文字压到下面内容上、总览变窄。原因是 `MarkdownText` 在 `sizeThatFits` 里直接改了 `NSTextView` 的排版宽度，SwiftUI 会用多个试探宽度调用它，最后留下的未必是实际宽度。现在改为在旁边用 `boundingRect` 测量，排版宽度跟随视图实际宽度。

**3. 问 Radar**
- **历史对话**：新表 `conversation`（迁移 v9）。每次提问后自动保存（含范围和每个回答的来源，重开后引用仍可点）；左侧对话列表可新建、切换、右键删除，可收起；标题取首问前 28 字；被打断的回答按已有内容标为已结束。
- **贴链接读网页**：问题里的 http(s) 链接（最多 3 个）先抓取正文再回答。GitHub `owner/repo` 读项目描述、星数、语言、许可证、主题与 README（`Accept: application/vnd.github.raw`）；其他页面取 article / main / body 的静态正文，单篇最多读 12000 字，送给模型时单篇最多约 7000 字。只贴链接时输出固定结构（一句话结论 / 要点 / 关键术语 / 值得追问的问题）；有具体问题则直接回答。PDF、纯 JS 页面、4xx/5xx 会明确提示，全部读不了就不回答，避免编造。
- **追问**：网页正文留在对话证据里；之后不带链接的追问不再判成“没有找到相关资料”，也不混入无关的已存条目。
- **一键阅读**：简报和回答里每条来源旁的书本图标，会新开一场对话并发送“帮我读一下这篇，整理要点：链接”。

**测试**：94 个（5 个联网类默认跳过），本轮新增 OpenAI 兼容客户端（模型列表、SSE、401/没填 Key、服务端错误）、概览判断、简报（有更新才调用模型、无更新零调用、历史存取、总览去引用）、链接提取、网页 / GitHub / PDF 读取、阅读模式提示词、追问不落入“没找到”、对话存取与中断恢复。

**真实限制（请知悉）**：
- **没有用真实的 OpenCode Go Key 连过**：协议按其文档（OpenAI 兼容的 `/v1/models`、`/v1/chat/completions`）实现并用模拟服务端测试。文档提到部分模型（如 MiniMax、Gemini 系）走别的协议，选中后可能报错，先选 GLM、Kimi 等走兼容接口的。
- **7 点定时、通知点击跳转、简报与阅读的实际文字质量**都需要真实模型和时间才能验证，本轮没有等到真正的 7 点。
- **上下文**：Ollama 的上下文固定为 10240（`num_ctx`），读长文或概览问题时每条资料会被截得更短；外部服务不受这个限制，但网页正文仍按上面的字数截断。
- 需要登录或拦截程序访问的网页读不到；读链接和外部模型都会让内容离开本机。

## V0.3.1：性能与稳定性回归

- **简报**：历史最多加载 400 天。

## V0.4：内置代理（借用 Clash Verge 的内核）——代码完成，待实测

- **目标**：Clash Verge 不开也能访问被墙的信息源，且 Clash Verge 开着时不冲突。
- **做法**：`Proxy.swift`。读取 `/Applications/Clash Verge.app` 里的 `verge-mihomo` 和 Verge 当前选中的订阅（只读，不改 Verge 的任何文件）；只取订阅的节点、策略组、规则，端口/模式/DNS 由 Radar 生成（回环地址、随机端口、`rule` 模式、无 TUN/系统代理/局域网/控制口），配置文件权限 600，放在 `Application Support/Radar/proxy/`；普通用户权限启动，启动前校验内核签名，复制 Verge 的 geo 库避免下载；退出时关闭，被强杀时由看门狗脚本结束内核，启动时清理残留。
- **选路**：三档，默认“关闭”。“自动”先探测直连（经系统设置，所以 Clash Verge 的 TUN/系统代理开着时直连通，Radar 不启动内核，避免两层代理）；不通才启动；之后直连恢复（例如打开了 Verge 的 TUN）就停掉。触发点：每次检查前（结果缓存 3 分钟/1 分钟/30 秒）、唤醒、网络变化、设置变更。内核意外退出最多自动重试 3 次/10 分钟。
- **接入**：抓取、外部大模型客户端走 `NetworkRoute.session`（代理时带 HTTP/HTTPS 代理字典，本机地址例外）；`js:` 页面渲染的 WKWebView 设置 `proxyConfigurations`；本机 Ollama 不经代理；网络错误附带“代理不可用/已走内置代理”提示以区分原因。
- **设置页**：模式、状态灯、重新检测、订阅更新/到期时间、订阅陈旧提示。
- **已知限制**：订阅不会自动刷新（要靠打开 Clash Verge 刷新）；未重放 Verge 的 Merge/Script 增强（你这份基本是空的）；暂不支持在 Radar 里换节点（用订阅策略组默认项）。
- **测试**：新增 ProxyTests（配置生成、订阅定位、选路决策、会话代理字典）。真实环境验收（关闭 Clash Verge 后访问被墙源；Verge 开 TUN 时不启动内核）留到最后做。

## V0.4.1：DeepSeek 官方服务与模型自动切换

- **新增服务预设“DeepSeek 官方”**（`https://api.deepseek.com`，模型 `deepseek-flash`）。请求带 `thinking: {type: disabled}` 关闭思考模式（默认开启，思考 token 按输出计费），仅对 `api.deepseek.com` 发送，其他服务不受影响。
- **每个服务各存各的 Key 和所选模型**：Keychain 项按主机名区分（OpenCode 沿用原来的项，不用重填），切换预设自动换成对应的 Key 和模型。
- **模型自动切换（`ModelFailover.swift`）**：所选模型在“还没输出任何内容”时被拒绝（400/402/403/404/408/409/422/425/429、5xx、超时、返回空内容），改用列表里最便宜的其他模型，最多试 3 个。已经开始输出就不再中途切换，避免拼接两个模型的答案；Key 错误、没填 Key、断网这类所有模型都会遇到的问题不切换，原样报错。失败的模型暂时避开（限流 5 分钟，服务端错误 10 分钟，不存在/无权限 1 小时），下次直接用可用的。
- **“便宜”的判断**：只能按名字猜（`ModelRanking`）——含 flash / mini / lite / haiku 等的优先；含 free 的排在便宜的付费模型之后（免费档最容易消失或限流）；含 pro / max / opus 等的靠后；minimax / gemini 在 OpenCode Go 上可能走别的协议，排最后。
- **模型缺省**：没选过模型，或所选模型已不在列表里，用“最便宜”的而不是字母序第一个。
- **可见性**：发生切换时，简报页和问 Radar 顶部显示“「X」HTTP 429，已自动改用「Y」”；简报记录的是实际回答的模型。设置里可关闭自动切换。
- **其他**：模型响应超时现在按“可切换”处理（原来误报成连不上）；403 不再一律当作 Key 无效。
- 测试 114 个（新增 FailoverTests：排序、切换、半截回答不切换、共性错误不重试、三次上限、失败后避开与恢复、关思考请求体）。
