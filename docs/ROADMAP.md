### 与现有能力的对照

| # | 现有可复用 | 还缺什么 |
| --- | --- | --- |
| 1 | GitHub Releases、GitHub 仓库发现、RSS、重大更新判定（正式版 major/minor） | 模型发布来源（如模型托管站的新模型 / 组织发布）；“适合本地部署”的判定规则（参数量、量化格式等）需要定义 |
| 2 | RSS / Atom 采集；AI 总结（时间范围、带来源编号） | 论文来源（arXiv 订阅 / 每日论文）与关键词过滤；“每周最值得阅读的五篇”的排序与固定模板（总结目前是手动触发） |
| 3 | GitHub Releases、重大更新判定 | “只提醒新功能、正式版本和重大行为变化”需要更细的过滤（从发布说明里区分新功能 / 修复 / 破坏性变化）；Claude Code 和 Codex 的发布渠道需先确认并试读 |
| 4 | 静态网页变化（含前后片段）、RSS、AI 总结 | 价格页、更新日志页的专用识别；“每周比较”需要跨关注事项的对比总结模板；JS 渲染的价格页目前读不了 |
| 5 | RSS、相关性过滤、AI 问答 | 社区来源（如 Hacker News 搜索接口、Reddit / V2EX 订阅）与热度门槛；三个主题的相关性规则 |

### 这五个雷达共同需要的能力

- **新增来源类型**：JSON 接口类来源（论文、模型托管站、社区搜索）。
- **每周总结**：固定模板的周报（排序 + 比较）。与“AI 只在用户点击时运行”有冲突，只能做成可选开关，默认关闭，或做成一键生成。
- **更细的“重要更新”判定**：基于发布说明的规则分级，而不是只看版本号。
- **信息源导入**：现在只能导出，补上导入后这些雷达才方便一键恢复。

## 二、其他值得做的雷达（来自你的补充）

原文摘录，未改动判断：

**创作选题雷达**
关注某个领域的一手消息、热门新产品、开源项目和研究论文，把重要变化转化为待制作选题。可以与现有 Research2Video 项目配合：Radar 负责发现，Research2Video 负责内容生产。

**安全漏洞雷达**
根据用户关注的软件或技术栈，监测安全公告。CISA 提供机器可读的 Known Exploited Vulnerabilities（已知被利用漏洞）JSON 数据。需要新增漏洞数据解析和软件名称匹配；注意 KEV 并非所有公开漏洞的完整列表。

**职业与机会雷达**
关注目标公司的招聘页、研究资助、比赛、开源悬赏等。价值很高，但初版建议只从公开、稳定的招聘和公告来源入手，不做跨全网招聘爬虫。

**政策与规则雷达**
关注特定领域的政策公告及条款变化。例如美国 Federal Register 提供无需 API Key 的公开文档检索 API。对不同国家或行业则需要寻找相应官方来源。

### 与现有能力的对照

| 雷达 | 现有可复用 | 还缺什么 |
| --- | --- | --- |
| 创作选题 | 多来源发现、事件合并、AI 总结、问 Radar | “把变化转成选题”的输出格式；与 Research2Video 的对接方式（导出文件还是共享数据）尚未定 |
| 安全漏洞 | 网页 / RSS 采集、事件与通知 | JSON 漏洞数据解析；软件名称到漏洞的匹配规则（误报风险大） |
| 职业与机会 | 静态网页变化、列表页识别 | 稳定的招聘 / 公告来源清单；列表页遇到 JS 渲染会读不到 |
| 政策与规则 | 网页 / RSS、变化片段对比 | 公开文档检索接口的解析；各国家或行业的官方来源需要逐个找 |

## 三、建议的先后顺序（待你确认）

1. 先补两种基础能力：JSON 来源类型、信息源导入。它们是上面多数雷达的前提。
2. 然后做论文雷达（2）和社区雷达（5），数据接口公开稳定，最容易验证。
3. 再做工具更新（3）和开源模型（1），重点是“重要更新”的细分规则。
4. 最后做需要跨关注事项比较和周报的（4）以及创作选题、安全漏洞等。

以上顺序是我的建议，还没有经过你确认；各来源的接口是否可用、字段是否符合预期，开工前都要先用真实数据试读。
