# Radar (v0.1, Lean R2)

macOS 原生信息雷达：自然语言建立关注 → 发现并试读信息源 → 定期直接采集 → 基线/去重 → 带原始链接的事件。

- 技术栈：SwiftUI · GRDB(SQLite) · FeedKit · SwiftSoup；无需任何 API Key（GitHub Token 可选，存钥匙串）。
- 构建：`scripts/build_app.sh` → `dist/Radar.app`（ad-hoc 签名，macOS 15+）。GRDB 以浅克隆放在 `ThirdParty/GRDB.swift`（官方仓库完整克隆在本机网络下过慢）。
- 测试：`swift test`（fixture + URLProtocol，A–F 六组行为）；真实联网：`RADAR_LIVE=1 swift test --filter LiveTests`。
- 数据库：`~/Library/Application Support/Radar/radar.sqlite`（环境变量 `RADAR_DB` 可覆盖）。

代码：`Sources/RadarCore`（Models/Fetch/Engine/Plan/Discovery）、`Sources/Radar`（SwiftUI App、菜单栏、设置）。

## 联网搜索信息源（新增）

设置里填 Exa API Key 后，主题类关注会先联网搜索，再对结果站点探测 RSS/Atom（按站点去重，跳过 GitHub 与社交站），探测通过的才作为候选列出。未填 key 时退回内置目录和 GitHub 搜索。已用 URLProtocol 桩测试；未用真实 key 实测（没有 key）。

## 第二轮迭代：发现与判断（真实运行结果）

- **GitHub 发现**：两个窗口合并（90 天内 ≥30★ 前 100 + 14 天内 ≥5★ 前 50），排除 fork/归档；“新项目”按创建时间判定，不是首次看到时间。门槛默认 50★（创建 14 天内降为 1/5，至少 10★），要求有描述且不是“只有星标没有 fork”，可在计划里改。
- **无 RSS 站点**：识别文章/项目列表页（最大同结构链接组，≥5 条；“Read more”类链接取卡片标题），每条独立去重。真实站点 thecontext.dev、research.meta.ai、index.zshipu.com 读取成功。
- **事件分级**：`newProject` / `majorUpdate`（正式版 major/minor 升级、标题含 release/发布等）/ `pageChange` / `update`。主题类关注只对前两类弹系统通知，其余只进列表。
- **跨来源合并**：同一关注下相同链接/GitHub 仓库/标题的内容只留一个事件，各来源出处合并显示。
- **自然语言**：验收句不再把“有真正值得关注的新项目时提醒我”当关键词；语义条件（如“创新”“中文”）列为“未生效”；Stars 门槛可一句话设置；修改关键词后自动重新发现并挂接新来源（不补报历史），对不再匹配的来源给出提示，来源可手动移除。
- **真实场景**（`RADAR_LIVE=1 EXA_API_KEY=… GITHUB_TOKEN=… swift test --filter ScenarioTests`）：来源发现 9 秒，7 个来源、567 条基线、0 事件；模拟新增后 31 条事件均带来源链接；重复检查 0 新事件；“也关注 MCP，排除 RAG”后新增 3 个来源，只记基线。
- **真实 App 驱动**（`RADAR_DRIVE_*`，见 ContentView.drive）：在运行中的 App 里走完新建→检查→暂停/继续→增量→自然语言修改，每步截图；来源 4→7，13 条事件，无重复 mergeKey。

**未解决**：没有用鼠标点过界面（osascript 无辅助功能权限，用 App 内置驱动代替，未验证真实点击与系统通知弹出）；LLM 辅助判断没有做（只有确定性规则，Foundation Models 本机不可用）；质量规则较粗，仍会放进少量低质量仓库；暂停期间出现的内容恢复后不补报；主题目录仍只有 AI 一类；JS 渲染页面不支持。

## 第三轮迭代：正确性与信息质量

- **事件合并漏报已修**：同一网页的新内容版本（同标题）逐次产生事件；仅在“同链接 / 同一 GitHub 项目（7 天内）/ 另一来源同标题（3 天内）”时才合并并保留各来源证据。同一来源复用标题、不同链接不合并。
- **已有项目重新获得关注**：GitHub 来源每次采集更新已有项目的 Stars/Forks；某个 Watch 的门槛被首次跨过时产生一次“项目升温”事件（12★→300★ 已测），已通知不重复，各 Watch 门槛独立，首次建立只记基线。搜索按星标分三个区间（14 天≥5、90 天 30–400、90 天 >400）取各自前 100，避免被高星项目挤掉；请求按 GitHub 限额自动间隔。
- **通知分类**：主题类 Watch 只对 `newProject` / `majorUpdate` 弹系统通知（`Engine.shouldNotify`），其余留在列表；通知开关仍有效。
- **质量规则**（用真实 ai-agents / local-llm / mcp 样本检查后调整）：相关性看名称+描述，仅靠 topic 标签命中时必须读起来像 AI 项目（CAD、UI 库、邮件工具被挡掉）；≥200★ 而 fork 不足 1% 视为虚高；ASCII 关键词按词首匹配（agent 不再命中 management）；同一仓库的文章与仓库事件归并。
- **测试**：34 个（3 个联网类默认跳过）。新增回归覆盖：同标题网页连续变化、跨来源重复、跨门槛一次提醒、未跨门槛、通知分类、自然语言排除生效、质量规则；`LocalServerTests` 用真实本地 HTTP 服务器，文件内容真的变化（页面、RSS、列表页、GitHub 指标），不改数据库；`RecheckTests` 对真实 GitHub 间隔 4 分钟重采：290 个项目中 15 个 Stars 真实变化，指标被更新，立即重查无新事件。LiveTests 里 `|| true` 的无效断言已删除。
- **真实 App 驱动**（无 key、真实 GitHub、真实等待 150 秒）：创建→暂停/继续→重采（509 个项目，18 个 Stars 变化，新增 1 个新项目事件）→“也关注 MCP，排除 RAG”新增 MCP 来源并保留旧来源。

**仍未解决**：没有用鼠标键盘实际点过界面（osascript 无辅助功能权限，仅 App 内置驱动）；系统通知弹出、菜单栏重新打开窗口、关闭窗口后后台继续监测未实测；真实 GitHub 上还没有等到某项目恰好跨门槛的实例（本地服务器测试覆盖）；Exa 联网发现本轮 App 内未重跑（上一轮已用真实 key 验证）；超过 90 天的旧项目突然走红不在搜索范围内；质量规则是确定性启发式，仍会有误判；LLM 判断未做。

## 真实界面操作验证（辅助功能授权后）

用 System Events 对 `dist/Radar.app`（临时数据库、真实 GitHub、无 key）做了真实的按钮按压与键盘粘贴：新建关注（输入验收句、分析、开始关注）→ 暂停/继续 → 立即检查 → 在自然语言框粘贴“也关注 MCP，排除 RAG”并点应用（关键词与排除更新，新增 MCP 来源，旧来源保留）→ 新建 RSS 关注，本地 feed 真实新增文章后立即检查，事件带原文链接 → 删除关注（无人使用的来源一并清掉）→ 关闭主窗口后 App 仍在运行，菜单栏“立即检查全部”仍会重采，“打开 Radar”重新打开窗口 → 菜单栏退出。

**未能验证**：系统通知横幅（事件已产生，但没有抓到横幅，授权状态未知）；真鼠标点击坐标/拖动（用的是辅助功能按压，不是物理鼠标）；Exa 联网发现的界面流程（本轮无 key）。
